OpenOps integrates with [Vantage](https://www.vantage.sh/) to automate workflows based on the cost data, recommendations, and alerts available through the Vantage API.

## Actions

OpenOps provides one [action](/workflow-management/actions) for interacting with Vantage:

<NarrowImage src="/images/vantage-actions.png" alt="Vantage actions" />

The Vantage action is based on the [Vantage API](https://docs.vantage.sh/api) and requires configuring a Vantage [connection](/cloud-access/access-levels-permissions) with a Vantage API key.

<NarrowImage src="/images/vantage-connection.png" alt="Configuring a Vantage connection" />

The following section describes the action available in the Vantage block.

### Custom API Call
Allows making arbitrary calls to any [Vantage API](https://docs.vantage.sh/api) endpoint:
- **URL**: Dynamic endpoint selection
- **Method**: `GET`, `POST`, `PATCH`, `PUT`, `DELETE`, or `HEAD`
- **Headers**: Optional (authorization auto-injected)
- **Query Parameters**: Optional
- **Body**: Optional JSON payload

## Designing a workflow

A typical Vantage workflow starts by retrieving recommendations or cost alerts from the Vantage API using the *Custom API Call* action, then iterating through them, determining the owner of the affected resource, and deciding whether to request an action from the owner. If the owner approves the action, the workflow can remediate the resource using the actions available for the [cloud platforms OpenOps supports](/cloud-access/supported-cloud-providers). Because the Vantage block exposes the API through *Custom API Call*, any endpoint documented in the [Vantage API reference](https://docs.vantage.sh/api) can be used from a workflow.

Below is a description of common patterns that can be implemented in your Vantage workflows.

### Handling recommendations via Slack or Microsoft Teams

For recommendations that require human judgment, OpenOps can send interactive messages that allow resource owners to approve, snooze, or archive optimization opportunities, or open a ticket, directly from Slack or Microsoft Teams. After retrieving recommendations, workflows can send a message with buttons for different responses using *Request Action* in the Slack or Microsoft Teams action block. Based on the user's decision, the workflow can proceed with remediation, create a ticket in your ticketing system, or call another Vantage endpoint with *Custom API Call* to record the decision. For environments such as development accounts, the approval step can be skipped so that remediation runs automatically.

See [Send a Slack notification with action buttons](/integrations/cloudhealth#send-a-slack-notification-with-action-buttons) in the CloudHealth guide for implementation details.

### Recommendation tracking using OpenOps tables and states

Rather than acting on each recommendation once and then losing track of its status, your OpenOps workflow can log Vantage recommendations to the preconfigured [*Opportunities* table](/reporting-analytics/tables#opportunities) for centralized tracking and status management (*Created*, *Under Review*, *Dismissed*, *Snoozed*). This approach prevents duplicate notifications, provides audit trails, and enables reporting on realized vs. unrealized savings across your organization.

Learn how to implement opportunity tracking by following the [CloudHealth recommendation logging workflow](/integrations/cloudhealth#look-up-the-opportunity-in-the-openops-table).
